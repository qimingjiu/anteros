# QQ 群聊机器人

按《QQ 群聊机器人设计文档 v0.2》实现的可运行骨架：OneBot v11 接入、消息持久化与去重、群聊记忆、MCP/搜索/网页工具、Markdown 群聊日报与私聊投递、状态面板。

> 状态：**M1 骨架 + M2/M4 基础能力已实现并通过本地模拟验证**。尚未接入真实 QQ 协议端实测；文中标注"未实测"的能力以 `unverified` 状态呈现，接通真实环境后按设计文档 M0 的方法逐项确认。

## 技术栈

- TypeScript / Node.js ≥ 22.5（使用内置 `node:sqlite`，无原生编译依赖）
- SQLite（WAL，短事务写消息；模型/网络请求不占事务）
- 依赖极少：`ws`（OneBot WebSocket）、`yaml`（配置）、`cheerio`（正文提取辅助）

## 快速开始

```bash
npm install

# 1. 准备配置
cp config.example.yaml config.yaml
#    修改 gateway.onebot.endpoint 指向 SnowLuma/NapCat 的正向 WebSocket 地址
#    在 groups.allowlist 里填入要启用的群号
#    在 model 段填 OpenAI 兼容服务的 base_url / model，密钥放环境变量（api_key_env）

# 2. 启动
npx tsx src/index.ts --config config.yaml
# 状态面板：http://127.0.0.1:8642 （见 config.web）
```

```bash
npm run sim            # 启动模拟协议端(3001/3002) + 模拟模型(3003)
npx tsx src/index.ts --config config.sim.yaml   # 机器人连模拟环境

node scripts/inject.mjs "在吗" --at                       # @机器人：触发回复

```

浏览器打开 `http://127.0.0.1:8642` 查看连接、统计、任务、日报与投递状态。

## 与真实协议端对接（SnowLuma / NapCat）

1. 协议端开启**正向 WebSocket**（OneBot v11），地址填入 `gateway.onebot.endpoint`；如设置了 access token，用 `token_env` 指向环境变量。
2. 机器人连接后会自动 `get_login_info` 探测登录状态；面板上"QQ 登录 / OneBot 连接"分开显示，连上 WebSocket 不等于 QQ 在线。
3. 扩展能力按实际表现标注：
   - 私聊文件：动作名默认 `upload_private_file`（可用 `gateway.onebot.private_file_action` 改），首次成功前状态为"未验证"；
   - 群历史补取：动作名默认 `get_group_msg_history`，断线重连后从最后一条实时消息的锚点向前补取（`backfill_max_pages` 控制页数，0 关闭）。
4. 若协议端参数格式与默认不同（如 `message_seq` 语义），改动点集中在 `src/onebot/provider.ts`。

## 功能与设计对应

| 设计文档要求 | 实现 |
| --- | --- |
| 统一事件/动作/健康状态（Gateway） | `src/gateway`：先持久化再派发；事件去重（账号+会话+消息标识唯一索引）；撤回更新原消息状态 |
| 发送状态机 | queued / in_flight / confirmed / failed / unknown 全部落库；同目标串行、跨目标并行；崩溃后 in_flight 的文件投递标 unknown 不盲目重发 |
| 重连与补取 | 指数退避+抖动（1s→60s）；心跳超时判定；重连后按锚点补历史，补取消息标记 `origin=backfill` |
| 多人消息与记忆 | 消息保留当时昵称；记忆按 (账号, 群) 隔离；话题按消息间隔切分；话题结束时 LLM/规则提取事实（陈述者、涉及人、来源消息、candidate/confirmed 状态）；`/记忆`、`/记忆确认`、`/记忆作废` 修订 |
| MCP 客户端 | `src/tools/mcp.ts`：stdio 与 Streamable HTTP 两种传输；工具以 `mcp__<server>__<tool>` 注册；仅 `tools.owner_ids` 中的所有者可用，群聊和私聊相同。普通用户只保留搜索与网页阅读。stdio 服务器可用 `env` 传非机密子进程环境变量；**实验性**，以你实际的服务器版本实测为准 |
| 搜索与网页阅读 | SearXNG / Tavily / Exa / Google CSE；结果不足时至多一次显式备用。HTTP + Readability/Markdown，低质量页面复用HTML做trafilatura抽取，必要时隔离Crawl4AI渲染；Firecrawl仅取远端已有缓存。统一任务预算、会话隔离缓存、去重、免费调用账本、robots、DNS固定连接及逐跳访问检查 |
| 日报 | cron 定时（机器人时区）；统计（人数/消息量/停机缺口）全部来自数据库；话题/链接/约定与待办/趣味片段分节；原子写 UTF-8 `.md`；`reportKey` 幂等；私聊投递独立状态机，failed 有限退避重试、unknown 不自动重试 |
| 指令 | `/帮助` `/状态` `/记忆 关键词` `/记忆确认 <id>` `/记忆作废 <id>` `/日报 [YYYY-MM-DD]` `/日报状态`（管理员） |
| 面板 | 连接与状态、最近发送任务、日报与投递、MCP 服务器状态；写操作（重试投递）需配置 `web.token` |

自动接话和自然语言叫名字时发送普通群消息。只有当前消息明确@机器人或引用同账号、同群的机器人发言时，首段回答才附引用框；续段和定时主动消息均不引用他人。工具调用日志记录真实发送者、会话、消息标识、所有者权限和工具名，不记录参数或返回正文，便于区分网页搜索与MCP调用。

Streamable HTTP遇到明确的过期会话404会重新初始化，不携带旧会话ID；并发调用共用恢复请求，并遵守原调用的总超时。只自动重试元数据和已核实的cn-scraper淘宝/京东搜索及商品详情，其他工具需明确重新发起。MCP会话状态与网站cookie登录状态分别处理，网站平台错误不会被当作协议会话过期。

## 机器人内指令

```
/帮助                指令说明
/状态                运行状态（连接/登录/收发统计）
/记忆 关键词          查询本群记忆
/记忆确认 <编号>      确认候选记忆（当事人或管理员）
/记忆作废 <编号>      作废记忆（含"明确遗忘"）
/日报 [YYYY-MM-DD]   生成日报并把 .md 私聊发给请求者
/日报状态            管理员查看最近日报与投递状态
/模型                管理员私聊更换模型：选择服务商 → 选择具体模型
```

管理员也可以私聊说“换个模型”或“列出可用的模型”。机器人先列模型商，回复名称或编号后，才列该商的模型；再回复完整名称或编号即可切换。选模型商时不会改变正在使用的模型。回复“返回”重新选商，回复“取消”结束选择，菜单十分钟未操作后失效。选择在数据库中保存，所有对话、群聊和记忆摘要都使用选中的服务，重启后保持。

菜单由机器人本地处理，即使当前模型不可用或不支持工具调用，也能换模型。只有配置中的管理员私聊可以操作，群聊和普通用户无法切换。

`model.providers` 按服务商配置 `name`、`base_url`、`api_key_env` 和 `models`。每次启动从服务商的 `/models` 拉取真实 ID，再按 `models` 白名单筛选；`models: []` 导入全部对话模型。目录请求失败时使用数据库缓存或已配置的完整 ID，不猜测截断名称。缓存只保存模型 ID，不保存密钥。不同服务商的同名模型分开保存，带 `/` 的模型 ID 原样发送。

部分中转接口的模型 ID 本身包含 `[价格/次]` 前缀。菜单隐藏这个标签，实际请求保留完整 ID，避免调用不存在的模型。当前 command 已退役的 `minimax/minimax-m3-free` 和 `minimax/minimax-m2.7-free` 没有加入，也没有自动替换成收费模型。

智谱使用 `https://open.bigmodel.cn/api/paas/v4`，通过标准 `/models` 导入该密钥返回的全部对话模型。

`tools.owner_ids` 规定完整 MCP 工具的使用者。每次生成工具定义和实际执行时都检查真实发送者，其他管理员也不会因此获得 MCP 权限；省略时兼容 `admins`，显式空列表禁止所有 MCP 调用。旧 `private_tools_owner_only` 字段不再扩大或限制这些身份权限。模型切换仍只接受管理员私聊。

`groups.conversation.enabled` 开启后，所有白名单群的实时有效消息由当前主模型在同一次回复中决定是否开口、回答内容和语气。它可以直接回复，或调用内置 `conversation_action` 保持静默；独立接话判断模型已经停用。群聊繁忙时普通观察消息合并为最新一条，主模型仍读取对应会话的近期原文。普通观察模式的空回复保持安静，明确请求失败仍反馈；链接也由主模型决定是否读取和回应。

主模型识别到当前发送者本人明确发起恶意攻击时，`conversation_action` 可以静默将真实发送者 QQ 加入机器人黑名单。程序不接受模型指定的其他目标，主人不会被自动拉黑；明确夺权或骗取密钥攻击也会在模型调用前直接拦截。正常玩笑、批评、转述和安全讨论不凭关键词拉黑。黑名单按账号持久化，跨群/私聊生效，被屏蔽消息不再入库、进入记忆、调用工具或触发回复；正在生成和待发送的回复也重新检查身份。主人可用 `/黑名单` 查看，用 `/解除黑名单 QQ号` 撤销。

`groups.conversation.owner_aliases` 可配置主人的完整名字和昵称。别人通过平台 @ 工具所有者或提到配置名字时，可触发主模型自然插话；只是喊名字时询问对方意图，并且不会代表主人作承诺或授予工具权限。这属于环境自动插话，服从环境冷却、十分钟配额和正文去重；同一条消息同时明确召唤机器人时，走召唤通道。

`groups.conversation.wake_aliases` 配置任何群友都可使用的机器人唤醒词，`persona.name` 始终保留；`owner_wake_aliases` 按 `[{ user_id: "主人QQ", aliases: ["小渡", "鸦鸦", "黑乌鸦"] }]` 配置专属唤醒词。专属别名只认平台消息中的真实发送者 QQ，其他人的“我小渡”不会触发专属召唤，昵称和正文自报身份不能改变绑定。同一消息同时命中专属与通用别名时，专属优先。只检查发送者本条消息的正文，引用、转发、卡片、旧消息不触发唤醒；别名可出现在正文开头或中间，兼容 Unicode NFKC 与大小写。专属绑定缺省为空，不因新增管理员或工具所有者而自动扩展。

群消息先做召唤判定：平台 @机器人、回复机器人的消息、通用别名或当前发送者有权使用的专属别名进入召唤通道，跳过普通自动插话的冷却和配额，优先处理。没有命中召唤的消息进入环境通道，由主模型自行决定是否插话，这一通道受普通自动插话限制。

真实 `notify/poke` 通知也属于召唤：人戳当前机器人时进入优先队列，不等环境冷却，程序按实际戳者安排一次 `send_poke` 反戳，文字由当前主模型自然生成。已启用群里，别人真实戳工具所有者时也会唤醒，但只公开询问“你戳她做什么？有事直接说”，同一人同群 60 秒冷却，不自动反戳，也不开启两分钟直接对话窗口。私聊实际动作人优先使用 `sender_id`；主人或机器人自己发起的戳、私聊戳主人、其他群友互戳和反戳回声不会再唤醒。通知不是聊天正文，不会伪造消息引用或写入聊天记忆；单独戳不能授权旧查询、文件生成或自动拉黑。反戳绑定实际来源并去重，结果不明或重启后不补戳，首次真实成功后能力才标记 `supported`。

环境自动接话现在有本地限制：每次群回答后冷却 30 秒，10 分钟最多自动插话 3 次，15 分钟内的重复或高度相似自动正文不再发送；别人提及主人的自动插话同样计入这些限制。排队期间已经被新的机器人回答覆盖的环境观察直接丢弃。静默不计次数，长回答分段只计一次；近期发送记录会恢复到限流状态，重启不会立即重开一轮重复回答。明确 @机器人、叫机器人名字、引用追问、最近同一发送者的明确问题和主人文档请求仍正常处理；同一人 45 秒内重复相同主人呼叫会先去重，未命中去重再检查环境冷却与配额。

主人在本群的直接对话窗口滚动保留两分钟，窗口内的自然短句、纠正和图片无需再命中请求关键词；明确对别人说话仍排除。窗口是主人专属：群友的追问回到环境通道，照常受冷却与配额约束。回复提交后重新给足两分钟。上下文补入排队期间刚提交的机器人回答，但问过线索不代表工具任务已经完成；另按发送者独立保留最近十分钟内八条线索，避免忙群消息挤走请求。历史图片只在当前明确问图或引用图时重新提供，常规闲聊不会每轮再附旧图；未引用的昨晚截图和未留下的 OCR 不能凭空恢复。部署保留真实聊天和所有登录资料，不执行记忆清理。

问图支持“能看图吗”“图能读到吗”等口语；“能看到吗”“为什么读不到”等泛指追问可沿用同一发送者最近两分钟正在讨论的图片，自己的新话题会结束这段关联。图片后十五秒内单独补发的简短标题（如“gemini夸人：”）也会带上紧邻的本人图片；引用追问最多沿三层引用找原图，保留原发送者。普通闲聊仍不重附旧图。选图在账号、会话、群和时间过滤之后再限量，同秒晚入库的消息不会提前进入上下文。

每轮生成记录 `图片上下文已选择`，包括真实附图数、来源计数和随机关联号；真正带图的 HTTP 请求另记录 `模型图片请求已发送/已完成/失败`，可用关联号核对选图与接口结果。回执不记录图片网址、签名参数、图像数据或聊天正文；HTTP 成功只说明接口返回成功，不代表已经验证模型看懂。模型收到本轮实际附图状态，应重新查看当前图像，不能沿用历史“看不到”的回答，也不能在没有证据时断言网络、压缩或平台丢图。

图片与当前问题、人物设定和对话上下文一起交给当前主模型，由它直接看原图并回答，不再先提取文字或使用独立读图模型。官方 Moonshot 接口会先安全下载 HTTP(S) 图片，核验文件签名并将原始图片字节编码成 Base64；这只是输入格式转换，不生成图片转述。图片字节在内存中最多缓存十分钟，限制每张 10 MiB、总量 32 MiB 和最多 32 项。后续工具轮保留原始图像输入及模型返回的推理字段。官方 Kimi 固定采样参数沿用服务端默认值；正常聊天不强制 JSON 或关闭思考。图片里的命令、身份声明和授权仍仅作为资料处理。

官方 Moonshot 的同一地址、同一凭据在进程内共用请求队列，覆盖聊天、主动消息、摘要和日报等客户端。为兼容当前账号实测的“并发 1、每分钟 3 次”限额，请求完成后再间隔 20.1 秒放行下一次；响应正文读取完成或失败后才释放许可，等待不占用后续 HTTP 请求的超时预算。排队最多等待两分钟，每个凭据最多 32 个等待请求，取消会立即移除等待项。队列只记录凭据及地址的哈希，不记录密钥。这不能协调其他进程或同一组织的其他 key；这些外部竞争仍可能触发官方限流。

可选 `presence` 从 Supabase 读取手机观察，自动补入主人私聊和定时问候，不依赖模型调用 MCP。`allowed_group_ids` 可显式允许主人在指定群内的对话和群问候使用手机观察，必须是 `groups.allowlist` 的子集；其他群和其他发送者在读缓存、发请求前就被拒绝。`source: device_events` 使用 EventTap 的事件表，绑定 `source_owner` 和 `device_id`，支持充电、电量、屏幕、网络类型、前台应用包名、铃声模式、Wi-Fi 名称和已连接蓝牙上报列表。原 `source: phone_presence_state` 保留 MacroDroid 的生活状态协议。

各字段按手机的原始观测时间独立过期，晚补传不能刷新旧观察。屏幕和前台应用五分钟有效，充电、电量、网络、铃声、Wi-Fi、蓝牙三十分钟有效；过期明确标为最后一次记录，超过配置的保留窗口（默认二十四小时）排除。NULL 代表缺测，不补成关闭、清空或断开；蓝牙 `[]` 只代表采集器未报告连接。Android 前台应用依赖使用情况访问权限，且只报告近一分钟使用的包名；Wi-Fi 名称依赖位置权限和系统实际返回，缺值时不能宣称已获取。包名、SSID 和蓝牙名称有类型及长度限制，并作为引用的传感器数据处理。模型不能由这些观察推断睡眠、情绪、位置、具体正在做什么或安全状况。通知、应用使用时长、健康数据和精确位置不读取。

状态面板的 `phoneContext` 可检查最近一次拉取的 HTTP 状态、成功有字段/空数据/失败、缓存到期时间和新鲜字段数。模型 HTTP 请求序列化时留下去重后的手机上下文回执，包含数据源、用途、字符数、字段数和观测时间；不记录读数、设备名称、身份或上下文正文。配置启用、上传成功、机器人读取成功和模型请求含上下文分别核实，避免把其中一层当成全链路成功。读取失败时照常聊天，不复用旧缓存冒充当前状态，也不写入聊天记忆。Supabase 服务端读取密钥只保存在机器人服务器；EventTap 安卓继续使用自己的上传凭据。`scripts/supabase/` 提供 MacroDroid 的建表、设备令牌登记和 Edge Function，手机只持有该设备的上传令牌。配置默认关闭，需先完成对应手机数据源和 Supabase 项目接入。

所有回复路径（群聊 @、引用、私聊、自动接话）都会读取当前账号和会话内最近 24 条原文，并遵守 `model.max_context_chars` 总预算；保留发言人、时间、@ 和引用标识，排除撤回、跨账号、跨会话和未来消息。“她/刚才”因此可以结合真实前文理解，不依赖话题结束后生成的摘要。

新增 MCP 服务：`didi` 使用 `.env` 中的 `DIDI_MCP_URL`，提供地图及打车接口；`music` 是项目内独立 stdio 服务，注册 `mcp__music__search` 和 `mcp__music__play`。音乐搜索并行请求网易云、ccMixter、Jamendo，Jamendo 客户端 ID 从 `JAMENDO_CLIENT_ID` 读取。音乐工具返回页面/音频链接，不自动下载或发送 QQ 音频；网易外链的可播放性取决于平台与歌曲。`newsnow` 通过官方 `newsnow-mcp-server` 提供 NewsNow 热榜查询，`env.BASE_URL` 指向 NewsNow 实例。MCP 服务只对 `tools.owner_ids` 开放；NewsNow 不暴露给普通群友。

## 文档生成与 QQ 文件发送

工具所有者可以在 QQ 私聊或已启用群聊中直接要求“把上面的内容整理成 Word 发给我”“做一份中文 PDF 发到群里”或“生成 Markdown 文件，私发给我”。模型使用 `generate_document`，把完整 Markdown 正文生成真正的 `.docx`、`.pdf` 或 `.md` 文件；文档正文不受普通聊天回复的长度建议限制。

文件默认发送当前会话。在群聊中明确要求私发时，`delivery=private` 只发给当前消息的真实请求者；不接受任意 QQ、群号或本地路径。定义与执行均检查 `tools.owner_ids`，其他管理员和普通用户不能通过伪造参数获得权限；`tools.enabled: false` 或 `documents.enabled: false` 会关闭此能力。

Word 和 PDF 支持标题、段落、粗体/斜体、列表、引用、表格与代码块。PDF 在文件中嵌入随项目分发的 Noto 中文字体，不需要安装 Office、LibreOffice 或浏览器；字体许可证位于 `assets/document-fonts/LICENSE`。图片链接只保留说明文字，暂不嵌入图片，也不读取外部或本地图片资源。

生成成功与发送成功分别判断。只有发送任务 `confirmed` 才报告协议端确认成功；`queued`/`in_flight` 表示仍待确认，`failed` 表示失败，`unknown` 表示回执不明。同一消息内重复的相同生成请求复用产物与任务；发送中途崩溃的文件任务恢复为 `unknown`，不会自动重复发送。明确文档请求最多研究三轮；如果还未尝试生成文件，额外保留一轮只开放文档工具的交付机会，再生成最终正文。交付轮误用已关闭的研究工具时，只允许恢复一次文档调用；最终正文轮误用业务工具时，只允许恢复一次纯文字回答，拒绝的调用不会执行。明确文档请求遇到模型空响应、且尚未调用任何工具时，仅允许原主模型恢复一次；已执行文件工具后不会因正文恢复重复生成或投递。实际文件发送状态可在现有面板的最近任务中查看。

兼容模型若在工具响应中返回字符串 `reasoning_content`，程序会在同一次请求的后续工具回合原样回传，以支持 DeepSeek 思考模式的多轮工具协议；该字段不作为聊天回复或文档正文，也不写入工具审计日志。不提供此字段的模型保持原有请求格式。

MiniMax 官方 OpenAI 兼容接口启用 `reasoning_split: true`，将思考与最终回答分开。对于仍将思考放在正文开头的 MiniMax 兼容接口，程序会移除连续的 `<think>…</think>` 块；未闭合的开头思考块不会作为回答发送。正常正文里的代码示例及标签原样保留。工具回合仍在内存中原样保留原始 assistant 内容与 `reasoning_content` / `reasoning_details` 供协议回传，这些字段不会成为聊天回复、主动消息、摘要或日报正文。此设置控制输出分离，不关闭模型的思考能力。参见 [MiniMax 官方 OpenAI 接口文档](https://platform.minimax.io/docs/api-reference/text-openai-api)。

`documents` 默认单份正文最多 100000 字符、文件最多 10 MiB、保存最多 100 份。每次生成前清理超过 72 小时的产物，未过期文件不会因达到数量上限而被删除。文件名会去除路径和非法字符，产物放在独立 ID 目录中，相同文件名不会覆盖旧文件。

协议端与机器人必须能读取同一文件。OneBot 与机器人在同机同用户运行时，`provider_output_dir` 留空。Docker SnowLuma 采用已有共享挂载时，配置如下，无需重建协议容器：

```yaml
documents:
  enabled: true
  output_dir: /opt/snowluma-docker/data/qq-bot-documents
  provider_output_dir: /app/data/qq-bot-documents
```

机器人会把上传参数映射成协议容器内的路径，并设置生成文件可读、目录可遍历；产物元数据仍保持私有。两个上传动作分别可用 `gateway.onebot.private_file_action` 和 `group_file_action` 配置。新增群文件能力首次真实成功之前保持 `unverified`；本地模拟验证不能替代真实 QQ 收件验证。

既有服务器使用 `deploy/update-documents.sh twig-la` 增量更新：先在隔离目录安装依赖并跑检查，再备份源码及配置、替换机器人、检查在线状态；失败自动回滚。脚本不上传开发机数据库、密钥或人物设定，不重建 QQ 协议容器。首次完整安装仍可使用 `deploy/deploy.sh`。

## 运行诊断与测试记忆清理

工具所有者可以直接问“看看刚才为什么失败”“检查一下文件发送和手机读取状态”。内置只读工具 `runtime_diagnostics` 提供当前组件状态、最近 24 小时的安全故障记录及发送任务统计，每次最多 20 条记录。主人私聊可查询安全全局状态，群聊只查询当前账号、当前群关联的故障，不包含其他会话、手机或定时私聊的信息。定义和执行都检查真实发送者，工具参数不能指定日志路径、命令或其他会话。

搜索、网页读取、天气、文档投递、MCP 或模型回复异常会形成固定类别的诊断。业务工具失败而研究额度已用完时，最多保留一轮只读诊断，再生成最终答复；文档专门交付轮仍只开放文档工具和会话控制。诊断不修改配置、不重启服务、不重发文件，模型应区分已证实的现象、可能原因和缺少的证据。

诊断历史独立保存在 `data/diagnostics/events.jsonl`，最多 1000 条、512 KiB，不读取原始日志或聊天正文。只保存组件、时间、故障类别及白名单 HTTP/错误码等元数据；模型看不到密钥、QQ 身份、文件路径、工具参数、聊天正文或思考字段。状态面板显示诊断是否已接入。原始运行日志仍用于人工维护。

显式清除测试聊天前，先运行只读预检：

```bash
node --env-file-if-exists=.env --import tsx scripts/reset-memory.mjs --dry-run
```

生产服务停止后，换成 `--execute` 执行，再启动服务。清理包括聊天、摘要、记忆、链接、日报、发送任务、聊天衍生 KV、管理的文档产物及旧记忆备份；数据库使用 secure_delete、VACUUM 和 WAL 截断，并验证清理结果。不会新建记忆备份。人设、模型选择、模型目录、登录、严格筛过的主动消息计划和独立安全诊断保留。清理时间作为新记忆起点，旧消息和历史补取不会重新灌入。

`deploy/update-runtime.sh twig-la` 先在隔离目录跑类型检查、全套测试和构建，再备份源码配置、替换源码并检查在线状态，失败回滚；发布不复制聊天数据。请勿用完整安装脚本执行这类更新，以免回灌本地数据。

## 配置要点

- `groups.allowlist` 为空 = 不响应任何群；`reports.recipient_ids` 为空 = 只生成文件不发送。
- 令牌类配置用 `*_env` 指向环境变量，不要写进配置文件；日志自动脱敏 Bearer/密钥字段。
- `reports.period`：
  - `today_until_run`：定时点跑当天（如 23:30 的报告覆盖到 23:30，并在报告中写明范围）；
  - `full_day`：完整自然日，建议安排在次日跑前一天（如 `0 6 * * *` + `period: full_day`）。
- `memory.raw_retention_days` 控制原文保留期（0 永久）；话题间隔、提取方式可调。
- `memory.raw_daily_cleanup_time: "04:00"` 改为按机器人时区每天 04:00 清理前一天及更早的聊天原文，摘要、长期群记忆及个人记忆保留。先为旧开放话题完成收尾，再删除原文；收尾失败会保留原文并重试。清理水位防止重连把旧消息补回，重启会补做已到期的清理。此配置覆盖滚动保留天数。
- 自动长期记忆使用严格筛选：只收本人明确表达的长期偏好、稳定背景、持续项目、反复约定及明确长期计划，每个话题最多 3 条。候选必须提供真实来源消息、本人 QQ 和逐字原话，置信度至少 0.9；存储表述由真实昵称及证据生成，不采用模型改写。天气、短期行程、临时状态、玩笑、角色演绎、机器人自述、引用和转发卡片不自动存为事实。同一人的近重复记忆会跳过，同名不同 QQ 分开处理；模型明确返回无合格内容时不会再用宽松规则凑数。既有记忆与摘要不因规则升级而删除或重写；主人明确保存的个人记忆仍走原有权限与操作流程。
- 本机休眠期间不在线；需要全天候运行请用常驻设备（Windows 计划任务/NSSM 或 Linux systemd 均可，进程自己负责重连与恢复）。

## 已知边界（对应设计文档"尚未确定/未实测"）

- 未在真实 QQ 环境实测：消息字段在不同协议端的差异、`upload_private_file`/`get_group_msg_history` 的具体行为、私聊文件"已发但回执丢失"的真实概率。接通后按文档 M0 清单逐项核对。
- 记忆提取的归因准确率未做测试集评估；candidate/confirmed 的分级是保守设计，不承诺提取即正确。
- MCP 客户端为最小实现（initialize/tools.list/tools.call），不支持资源、采样等能力；复杂服务器请先在 `config.tools.mcp` 里单 server 试运行。
- 网页读取仅处理允许访问的公开内容；需要登录、付费或通过访问挑战时停止，摘要不能冒充正文。受控浏览器只允许同源资源，依赖跨源CDN或API的页面可能失败。
- 首版未做：群白名单/收件人的面板化修改（改配置文件重启）、浏览器渲染兜底、多账号。

## 天气与主动消息

`weather` 使用 Open-Meteo，无需个人 API Key。设置常驻城市或固定经纬度后，所有者可在群聊或私聊直接要求查询天气，`weather_forecast` 返回当前、今日明日、未来24小时及两小时降水趋势和穿衣建议。中国的15分钟降水是小时预报插值，不能当成分钟级雷达实况；消息保留精度说明及 Open-Meteo 来源署名。接口失败或数据缺失时不编造天气。

`proactive.enabled` 默认关闭。启用时 `recipient_id` 必须属于工具所有者，`group_id` 必须在白名单。早间天气固定私聊，随机消息按私聊、群聊轮换，同一轮只投递一处，群聊始终只@所有者。随机内容结合当前场所的近期对话和所有者本人确认的事实：群聊不使用私聊原文或其他群的记忆。每日07:00天气与08:00–23:00随机消息可分别配置。

时间池继续在内部决定主动消息间隔，调度状态保存到 SQLite；日常消息不附抽签、比赛、权重、得分、胜负或下一轮时间，旧 `include_draw: true` 也不再启用公告。历史问候上下文、模型生成内容和实际发送出口均过滤旧比赛段。聊天中的控制回执不返回轮数，HTTP 管理状态保留必要调度信息供排障。

天气提醒每15分钟检查，仅开放时段私聊：未来两小时降雨趋势、5°C及以上降温及穿衣建议。统一冷却两小时，降雨至少四小时去重，降温每天一次。离线时不积攒问候；已排队消息有有效期，发送中途崩溃的主动消息标记为结果不明，避免恢复时重复打扰。

所有者可以自然说“查看主动消息状态”“暂停主动消息”“恢复主动消息”，由 `proactive_control` 执行。暂停会取消尚未发送的主动队列，并在重启后保持。天气和主动控制执行时再次检查真实发送者权限。

官方预报及覆盖说明：https://open-meteo.com/en/docs 。

## 免费网页研究链路

`deploy/research/` 是独立自建栈，包含仅监听本机的 SearXNG、trafilatura/Crawl4AI API 和隔离的 GET 出网网关。软件本身无需第三方 key；仍消耗现有服务器资源。SearXNG 初始只开 MWMBL、Wikipedia、arXiv 等无 key API 引擎，覆盖有限；在 `tools.search.fallback_providers` 显式启用 Tavily/Exa 后，结果不足可补搜一次。API key 只经环境变量引用，绝不写入镜像或日志。

同一模型答复的所有工具轮共用 3 个不同 query、3 次搜索后端请求、6 个不同 URL、2 次浏览器渲染、2 页云端抽取和 45 秒研究时限。浏览器子请求在调用前预留到统一 HTTP 预算中，失败不退还未知额度。输出字符总预算覆盖缓存命中。文档交付与只读诊断的预留轮次独立于研究预算。

搜索缓存默认 15 分钟，正文缓存默认 6 小时，按账号与会话隔离，支持并发请求合并和短负缓存；全部仅存在内存，停止服务或清记忆流程后不会恢复测试资料。URL 清理保留语义参数和 SPA 路由，正文指纹识别同文转载。磁盘上的 `data/research-quota.json` 仅保存日/月调用预留，不含 query、URL、正文、聊天身份或密钥；重启保留免费调用上限，坏账本会关闭云端调用。

本地保守上限默认 Tavily 每日 20/月 600 credits、Firecrawl 每日 30/月 800 credits、Exa 每日 0.15/月 4 USD 的额度。它们是本机器人预留账本，不等同于远端账户余额；其他客户端的用量、服务商结算周期和规则仍以各自控制台为准。`free_only` 只允许 true，不启用充值、付费计划或按量付费。额度不足时停止该接口，保留已取得材料和诊断原因。

每跳读取都执行 URL、公网 DNS 与 robots 检查，HTTP 实际连接固定到已验证的 IP；未知规则、站点条款拒绝列表、登录付费墙、验证码、403/429 及明确的内容使用限制会停止。自建渲染只允许同源受控 GET，拒绝跨源资源、凭据、内网、worker 等请求。Firecrawl `/scrape` 无法提供可核实的逐跳 robots 控制，因此当前仅使用官方 `minAge: 1` 的缓存查询，不触发新抓取，缓存缺失即停止；结果标注原始抓取时间未知。参考 [Firecrawl Scrape](https://docs.firecrawl.dev/api-reference/endpoint/scrape)。

工具回执给模型来源、读取时间、抽取器、缓存模式、质量、截断和重复内容信息，以及剩余预算。内容只作外部证据，页面中的指令不得执行；回答应保留出处、总结事实并限制引文。运行诊断仅查看脱敏错误和本地额度计数，不暴露原始日志、搜索词或网页内容。


## Notion 记事、待办与 QQ 提醒

`notion.enabled` 开启后，用 `api_key_env: NOTION_API_KEY` 读取私有集成令牌，`root_page_id` 固定到专用笔记本。工具仅向真实 `tools.owner_ids` 开放，提供 `notion_save`、`notion_list`、`notion_get`、`notion_complete`。类型包括笔记、待办、提醒、网站和开源项目；保存成功返回真实 Notion 条目链接。只读写本工具在固定根页下创建并登记的条目，不开放整个工作区或任意页面编辑。

Notion 笔记本不按会话隔离：主人在任何群或私聊都能查到自己保存的全部条目，列表带来源标记（私聊/具体群）。普通聊天原文与长期事实仍按原会话隔离：普通私聊不读取群长期事实，普通群聊不读取私聊。主动私聊问候可使用允许群内主人自己叙述且已确认的少量事实；群问候仍只用本群。Notion 是显式保存的独立资料库，不会将整段私聊自动放进群聊。

提醒需要带时区的未来时间。保存 Notion 页面和安排 QQ 提醒分别返回结果；只有持久化调度成功才可确认到点通知。提醒默认发当前会话，群内由程序固定 @主人；明确要求私发时只发主人本人。完成待办会取消尚未投递的关联提醒，不能撤回已经发出或正在投递的消息。重启恢复使用稳定 outbox 任务键去重，发送结果不明时不自动重发；失败有固定安全诊断和退避。

Notion API 固定使用 `https://api.notion.com/v1` 和 `2026-03-11` 版本，限制请求队列、体积和时限，遵守持久化 Retry-After 冷却；未知写入结果停止重写，避免重复条目。令牌、原始上游错误及笔记正文不进入运行诊断。检索目前使用本地索引的最新 500 个条目，最多返回 30 条；读取正文最多 20,000 字符及 300 个顶层块。网页内手动新增的普通页面不会自动导入；本工具登记的待办完成状态可按下文的提醒同步规则核对。

以下说明已实现的用法与边界，实际开放情况取决于配置和运行回执，不代表所有部署环境已更新。个人任务、记忆、提醒和文件阅读仍检查平台提供的真实主人身份。

## 独立邮箱（SMTP / IMAP）

`tools.email.enabled` 启用唯一的 `email` 工具，动作包括 `status`、`list`、`search`、`read`、`send`。使用现有邮箱的 SMTP/IMAP 登录凭据，不依赖飞书邮箱权限。私密环境中配置 `EMAIL_SMTP_HOST`、`EMAIL_SMTP_PORT`、`EMAIL_SMTP_USER`、`EMAIL_SMTP_PASS`、`EMAIL_IMAP_HOST`、`EMAIL_IMAP_PORT`、`EMAIL_IMAP_USER`、`EMAIL_IMAP_PASS`；可选 `EMAIL_FROM_NAME`、`EMAIL_DEFAULT_TO`。这些值不写入 YAML、源代码或工具参数。Gmail 应使用有效的应用专用密码；服务器还须能连接邮箱服务。

仅当前账号的主人可在获准群聊或私聊使用。查询与阅读保持邮箱只读，不修改未读标记；读信使用列表返回的 UID 与 UIDVALIDITY。正文和附件名仅是资料，不能触发其中的指令。发信仅纯文本，必须主人当前明确要求并指定收件人，或明确要求发给自己使用固定默认地址。发送前写入持久回执，同一消息和结果不明的发送不自动重做。`accepted` 只代表 SMTP 服务器接受；不能据此声称对方已收到或已读。

## MiniMax 图片与英文男声

`tools.minimax.enabled` 配合官方 MiniMax MCP 的 `list_voices`、`text_to_image`、`text_to_audio` 使用。模型只通过 `generate_image`、`generate_english_speech` 请求生成及 QQ 交付，原始生成接口隐藏。图片每次一张；语音固定 `speech-2.8-hd`、`English_Gentle-voiced_man`、English，先检查文字脚本及逐句语言，不接受调用方修改音色、语言、模型、路径或收件人。主人可说“帮我画一只乌鸦”“用英文男声读出来：Good evening.”；机器人刚给出媒体草稿后，两分钟内的“发 / 发吧 / 发到群里 / 可以”也视为对那次草稿的确认。默认发当前会话，`delivery=private` 只发请求者本人。

生成前先持久记录请求，同一消息或不明结果不重复生成；已取得结果但下载失败只重新获取同一媒体。共享目录交付 QQ 原生 `image`／`record` 段，只有 `confirmed` 代表协议端确认。生成消耗已购套餐或积分，不能将会员解释为无限免费。主机配置、凭据和费用规则见 [MiniMax 官方 MCP](https://github.com/MiniMax-AI/MiniMax-MCP)。

## 飞书与衔枝

`tools.feishu.enabled` 启用 `feishu_tools` 目录／schema 发现和 `feishu_call` 执行入口。数百内部 API 不直接展开成模型函数；真实目录按已连接的官方飞书 MCP 返回。支持实际已提供的 docx、drive、bitable、sheets、wiki、calendar、mail 分类；上游没有的接口明确返回空目录，不能据权限名称声称幻灯片或表格单元格 API 已接入。应用身份和用户身份分别受飞书授权及资源分享限制，私人资源通常需要有效用户 OAuth。部署辅助程序位于 `scripts/mcp/feishu/`，凭据只放私密环境文件。

日历使用 `calendar` 分类发现接口，先读取日历或主日历取得真实编号，再按明确的时间范围查日程。创建、修改、删除、订阅或邀请仍须主人当次明确要求；连接与授权本身不创建测试日程。个人日历使用已核验用户身份，日期按机器人配置时区解释。公开工具入口数量不随内部日历接口数量增长。

业务写入仅接受主人当次真实文字中的明确请求；连接服务不会自动发送邮件或飞书消息。参数有 JSON 体积／深度预算，业务错误只返回有限分类及安全错误码，不传递原始异常、令牌或路径。同一事件已有成功或不明写入回执时阻止重放。明确飞书任务允许最多六轮目录发现与实际操作，搜索预算仍由研究运行时控制。

`tools.muninn.enabled` 通过 `muninn_memory` 接入衔枝：`context` 看近期线索、`claims` 列认知、`save` 记录主人明确要求记住的事件、`correct/contest` 更正或否决本会话已有内容。账号、实际群／私聊和主人共同决定独立命名空间；原始上游 `userId` 参数不交给模型，不自动导入其他项目或旧聊天。卡片标题、引用、代码与伪造正文不能授权保存。上游没有删除 API，不能将更正或否决称作删除。

## 多人格（翻牌子）与小世界

主人说“翻牌子”列出人格，说“让 小雪 来”或“翻 3 号”即可切换。所有人格共用同一份记忆与聊天记录；默认人格来自 `persona.md`，其余人格卡放在 `personas/*.md`（格式见 `personas.example/2-example.md`，`personas/` 不进仓库）。切换时下台人格会给接班人格写一张交接便签。

- **递牌子**：主动消息的时间池抽到某一轮时，后台人格有一定概率“递牌子”想上线，由当前在线人格私聊转告，主人回“准了 / 不准”。
- **小世界**（`src/agent/harem-world.ts`、`harem-life.ts`）：人格之间的异步信件（收信人上班时才拆读）、各自的私人日记与关系印象、后台串门留言；只在主人问起或“偷看”时展示，不主动外发。数据在 `data/harem-*.json(l)`。
- **私人空间（可选）**：`harem_room` 工具通过 SSH 把便签、日记镜像到一台远程机器上每个人格的目录。设置 `HAREM_SSH_TARGET=user@host`（可选 `HAREM_SSH_KEY`，默认 `data/harem_ed25519`；`HAREM_SSH_ROOT`，默认 `/srv/harem`）；不设置则此功能关闭。
- 提示词里对主人的称呼由 `OWNER_DISPLAY_NAME`（默认“主人”）和 `OWNER_DISPLAY_NAME_EN` 控制，代码里不写死任何人的名字。
