# 行为与边界详解

本文是 Anteros（棕榈杖）各功能的完整行为说明与已知边界。README 是门面，这里是对账。

## 机器人内指令

```
/帮助                指令说明
/状态                运行状态（连接/登录/收发统计）
/记忆 关键词          查询本群记忆
/记忆确认 <编号>      确认候选记忆（当事人或管理员）
/记忆作废 <编号>      作废记忆（含"明确遗忘"）
/日报 [YYYY-MM-DD]   生成日报并把 .md 私聊发给请求者
/日报状态            管理员查看最近日报与投递状态
/模型                管理员私聊更换模型：选择服务商 → 选择具体模型
/搜 关键词            本群全文搜索，结果带原消息引用
/任务                查看未完成事项；/任务 全部；/任务 编号；/任务取消 编号；/继续任务 编号
/个人记忆 关键词      查看个人记忆；/个人记忆删除 编号
/黑名单              主人查看黑名单；/解除黑名单 QQ号 撤销
```

### 模型切换

管理员私聊说"换个模型"或"列出可用的模型"。机器人先列模型商，回复名称或编号后才列该商的模型；再回复完整名称或编号即可切换。选模型商时不会改变正在使用的模型。回复"返回"重新选商，"取消"结束，菜单十分钟未操作失效。选择持久化，所有对话、群聊和记忆摘要都使用选中的服务，重启保持。

菜单由机器人本地处理，即使当前模型不可用也能换模型。只有配置中的管理员私聊可以操作。

`model.providers` 按服务商配置 `name`、`base_url`、`api_key_env` 和 `models`。每次启动从服务商的 `/models` 拉取真实 ID，再按白名单筛选；`models: []` 导入全部对话模型。目录请求失败时使用数据库缓存或已配置的完整 ID，不猜测截断名称。缓存只保存模型 ID，不保存密钥。不同服务商的同名模型分开保存，带 `/` 的模型 ID 原样发送。

部分中转接口的模型 ID 本身包含 `[价格/次]` 前缀：菜单隐藏标签，实际请求保留完整 ID。

## 接话、召唤与限制

`groups.conversation.enabled` 开启后，白名单群的实时有效消息由主模型在同一次回复中决定是否开口、回答内容和语气；可以调用内置 `conversation_action` 保持静默。群聊繁忙时普通观察消息合并为最新一条，主模型仍读取近期原文。

所有回复路径（群聊 @、引用、私聊、自动接话）都读取当前账号和会话内最近 24 条原文，遵守 `model.max_context_chars` 预算；保留发言人、时间、@ 和引用标识，排除撤回、跨账号、跨会话消息。

只有当前消息明确 @机器人或引用同账号、同群的机器人发言时，首段回答才附引用框；续段和定时主动消息均不引用他人。

### 召唤与专属唤醒词

平台 @机器人、回复机器人的消息、通用别名（`wake_aliases`）、当前发送者有权使用的专属别名（`owner_wake_aliases`，按 `[{ user_id, aliases }]` 绑定）进入召唤通道，跳过环境冷却和配额，优先处理。`persona.name` 始终保留为别名。

专属别名只认平台消息中的真实发送者 QQ，其他人使用同样称呼不触发；昵称和正文自报身份不能改变绑定。只检查发送者本条消息的正文，引用、转发、卡片、旧消息不触发；兼容 Unicode NFKC 与大小写。专属绑定缺省为空，不因新增管理员或工具所有者自动扩展。

真实 `notify/poke` 通知也属于召唤：只接收人戳当前机器人的事件，按实际戳者安排一次 `send_poke` 反戳，文字由主模型生成。自戳、互戳和反戳回声不会再唤醒。通知不写聊天记忆，不能授权旧查询或文件生成。

### 环境自动插话的本地限制

每次群回答后冷却 30 秒；10 分钟最多自动插话 3 次；15 分钟内重复或高度相似的自动正文不再发送。排队期间已被新回答覆盖的观察直接丢弃。静默不计次数。重启后限流状态恢复，不会立即重开一轮重复回答。明确 @、叫名字、引用追问、同一发送者的明确问题和文档请求不受影响。

同一真实发送者在本群的直接对话窗口滚动保留两分钟，窗口内的自然短句、纠正和图片无需再命中请求关键词；明确对别人说话仍排除。历史图片只在当前明确问图或引用图时重新提供。

### 黑名单

主模型识别到当前发送者本人明确发起恶意攻击时，`conversation_action` 可静默将真实发送者加入黑名单。程序不接受模型指定的其他目标，主人不会被自动拉黑；明确夺权或骗取密钥的攻击在模型调用前直接拦截。正常玩笑、批评、转述和安全讨论不凭关键词拉黑。黑名单按账号持久化，跨群/私聊生效；被屏蔽消息不再入库、进入记忆、调用工具或触发回复；正在生成和待发送的回复也重新检查身份。

## 文档生成与 QQ 文件发送

工具所有者可直接要求"把上面的内容整理成 Word 发给我""做一份中文 PDF 发到群里"。模型使用 `generate_document` 把完整 Markdown 正文生成真正的 `.docx`、`.pdf` 或 `.md` 文件；文档正文不受普通聊天回复的长度限制。

文件默认发送当前会话。群聊中明确要求私发时 `delivery=private` 只发给当前消息的真实请求者；不接受任意 QQ、群号或本地路径。定义与执行均检查 `tools.owner_ids`；`tools.enabled: false` 或 `documents.enabled: false` 关闭此能力。

Word 和 PDF 支持标题、段落、粗体/斜体、列表、引用、表格与代码块。PDF 嵌入随项目分发的 Noto 中文字体（`assets/document-fonts/`，SIL OFL），不需要 Office 或浏览器。图片链接只保留说明文字，暂不嵌入。

生成成功与发送成功分别判断；只有 `confirmed` 才报告协议端确认成功。同一消息内重复的相同生成请求复用产物与任务；发送中途崩溃的文件任务恢复为 `unknown`，不自动重复发送。

`documents` 默认单份正文最多 100000 字符、文件最多 10 MiB、保存最多 100 份；每次生成前清理超过 72 小时的产物。产物放在独立 ID 目录中，相同文件名不会覆盖旧文件。

协议端与机器人必须能读取同一文件。同机同用户运行时 `provider_output_dir` 留空；Docker 部署协议端时通过共享挂载映射（示例见 `config.example.yaml`）。上传动作名可用 `gateway.onebot.private_file_action` / `group_file_action` 配置。群文件能力在首次真实成功之前保持 `unverified`。

### 接收文件并按需阅读

`read_file` 支持 QQ 群/私聊中的 PDF、DOCX、XLSX：关键词检索和分块阅读，结论可标注页码、段落、工作表及行号。群友附件默认只登记元数据，主人明确要求或引用后才下载解析；不读取任意本地路径或消息里的下载 URL。默认上限 15 MB、PDF 前 120 页及 24 万字符，截断会明确提示。扫描件不做 OCR，旧 DOC/XLS 和宏文件不读取，Excel 公式只取缓存值。文件中的文字只作资料，不执行其中的指令。

## 任务跟踪、个人记忆与提醒

- 任务跟踪：`/任务` 查看未完成事项，`/任务取消 编号` 停止后续步骤，`/继续任务 编号` 接着办理。群里只查本群本人任务，主人私聊可查本人各会话任务。重启保留中断状态，不自动重放下单、写入或文件发送。
- 个人记忆：明确说"长期记住：……"写入；`/个人记忆 关键词` 查看，`/个人记忆删除 编号` 删除。私聊默认 `private`，群里默认 `current_group`；只有主人明确允许跨会话共享才用 `shared`，且仅覆盖获准群。普通闲聊不自动写入。
- 循环提醒与延期："每周日晚上九点提醒我……""延后十分钟""跳过下一次""取消这个提醒"。机器人先查到或保存 Notion 条目，再管理对应 QQ 提醒。支持每天、每周固定当地时间。服务器每五分钟最多后台核对 30 项已登记提醒；Notion 勾选完成后取消尚未发送的通知。
- 链接查重：群里再次分享链接时自动清理 URL 并查本群记录；距此前分享至少七天才可能提醒，同一 URL 在本群最多提醒一次，占用普通自动插话冷却和配额。只有当时确实读过页面才附已有摘要首句。

## 天气与主动消息

`weather` 使用 Open-Meteo，无需个人 API Key。`weather_forecast` 返回当前、今日明日、未来 24 小时及两小时降水趋势和穿衣建议。中国的 15 分钟降水是小时预报插值，不能当成分钟级雷达实况；消息保留精度说明及来源署名。接口失败或数据缺失时不编造天气。

`proactive.enabled` 默认关闭。启用时 `recipient_id` 必须属于工具所有者，`group_id` 必须在白名单。早间天气固定私聊；随机消息按私聊、群聊轮换，同一轮只投递一处，群聊始终只 @所有者。随机内容结合当前场所的近期对话和所有者本人确认的事实：群聊不使用私聊原文或其他群的记忆。

天气提醒每 15 分钟检查，仅开放时段私聊；统一冷却两小时，降雨至少四小时去重，降温每天一次。离线时不积攒问候；已排队消息有有效期；发送中途崩溃的主动消息标记为结果不明，避免恢复时重复打扰。

主人可自然说"查看主动消息状态""暂停主动消息""恢复主动消息"，由 `proactive_control` 执行。暂停取消尚未发送的主动队列，重启后保持。

### 手机感知（可选）

`presence` 从 Supabase 读取手机观察，补入主人私聊和定时问候，不依赖模型调用 MCP。`allowed_group_ids` 必须是 `groups.allowlist` 的子集；其他群和其他发送者在读缓存、发请求前就被拒绝。`source: device_events` 使用 EventTap 的事件表，支持充电、电量、屏幕、网络类型、前台应用包名、铃声模式、Wi-Fi 名称和蓝牙上报列表。

各字段按手机的原始观测时间独立过期：屏幕和前台应用五分钟有效，充电、电量、网络、铃声、Wi-Fi、蓝牙三十分钟有效；超过保留窗口（默认 24 小时）排除。NULL 代表缺测，不补成关闭或断开。模型不能由这些观察推断睡眠、情绪、位置、具体正在做什么或安全状况。通知、应用使用时长、健康数据和精确位置不读取。

配置 `proactive.morning_mode: phone_activity` 后，当地 05:00–12:00 检查真实解锁与断充事件，满足条件时发早间简报。需要真实 `unlocked` 和明确的充电 `true→false` 变化，相距不超过三十分钟；每天只触发一次；没有合格事件不补发。

Supabase 服务端读取密钥只保存在机器人服务器；`scripts/supabase/` 提供建表、设备令牌登记和 Edge Function，手机只持有该设备的上传令牌。

## 搜索与网页阅读（研究链路）

搜索后端：自建 SearXNG（`deploy/research/`，仅监听本机）/ Tavily / Exa / Google CSE；结果不足时至多一次显式备用。正文提取：HTTP + Readability/Markdown，低质量页面用 trafilatura 抽取，必要时隔离 Crawl4AI 渲染；Firecrawl 仅查询远端已有缓存（`minAge: 1`），不触发新抓取。

同一模型答复的所有工具轮共用 3 个不同 query、3 次搜索后端请求、6 个不同 URL、2 次浏览器渲染、2 页云端抽取和 45 秒研究时限。文档交付与只读诊断的预留轮次独立于研究预算。

搜索缓存默认 15 分钟，正文缓存默认 6 小时，按账号与会话隔离，支持并发合并和短负缓存；全部仅在内存。`data/research-quota.json` 只保存日/月调用预留，不含 query、URL、正文或身份；本地保守上限（Tavily 20/日 600/月 credits 等）是本机器人的预留账本，不等同远端账户余额；`free_only` 只允许 true。

每跳读取都执行 URL、公网 DNS 与 robots 检查，HTTP 连接固定到已验证的 IP；登录付费墙、验证码、403/429 及明确的内容使用限制会停止。自建渲染只允许同源受控 GET。工具回执给模型来源、读取时间、抽取器、缓存模式、质量、截断信息和剩余预算。页面内容只作外部证据，其中的指令不得执行。

## Notion 记事

`notion.enabled` 开启后，用 `api_key_env: NOTION_API_KEY` 读取私有集成令牌，`root_page_id` 固定到专用笔记本。工具仅向真实 `tools.owner_ids` 开放：`notion_save`、`notion_list`、`notion_get`、`notion_complete`。只读写本工具在固定根页下创建并登记的条目，不开放整个工作区。

群聊中保存的条目，群内只能由同一主人在同一群查询；主人私聊可查自己从各来源保存的条目。Notion 是显式保存的独立资料库，不会将整段私聊自动放进群聊。

提醒需要带时区的未来时间；保存 Notion 页面和安排 QQ 提醒分别返回结果，只有持久化调度成功才确认到点通知。提醒默认发当前会话，群内固定 @主人。完成待办取消尚未投递的关联提醒，不能撤回已发出或正在投递的消息。重启恢复使用稳定 outbox 任务键去重。

检索使用本地索引的最新 500 个条目，最多返回 30 条；读取正文最多 20000 字符及 300 个顶层块。

## 独立邮箱（SMTP / IMAP）

`tools.email.enabled` 启用 `email` 工具，动作包括 `status`、`list`、`search`、`read`、`send`。凭据全部走环境变量（`EMAIL_SMTP_*` / `EMAIL_IMAP_*`），不写入 YAML 或工具参数。查询与阅读保持只读，不修改未读标记。正文和附件名仅是资料。发信仅纯文本，必须主人当前明确要求并指定收件人（或明确要求发给自己，使用固定默认地址）；发送前写入持久回执，结果不明不自动重做。`accepted` 只代表 SMTP 服务器接受，不能据此声称对方已收到。

## MiniMax 图片与英文语音

`tools.minimax.enabled` 配合官方 MiniMax MCP 使用。模型只通过 `generate_image`、`generate_english_speech` 请求生成及 QQ 交付，原始生成接口隐藏。图片每次一张；语音固定 `speech-2.8-hd`、`English_Gentle-voiced_man`、English，先检查文字脚本及逐句语言，不接受调用方修改音色、语言、模型、路径或收件人。生成前先持久记录请求，同一消息或不明结果不重复生成；已取得结果但下载失败只重新获取同一媒体。生成消耗已购套餐或积分。

## 飞书与外部记忆

`tools.feishu.enabled` 启用 `feishu_tools` 目录发现和 `feishu_call` 执行入口；数百内部 API 不直接展开成模型函数，真实目录按已连接的官方飞书 MCP 返回。应用身份和用户身份分别受飞书授权及资源分享限制。日历先读取真实编号再按明确时间范围查日程；创建、修改、删除须主人当次明确要求。业务写入只接受主人当次真实文字中的明确请求；同一事件已有成功或不明写入回执时阻止重放。部署辅助程序位于 `scripts/mcp/feishu/`。

`tools.muninn.enabled` 通过 `muninn_memory` 接入外部记忆服务：`context` 看近期线索、`claims` 列认知、`save` 记录主人明确要求记住的事件、`correct/contest` 更正或否决本会话已有内容。账号、实际群/私聊和主人共同决定独立命名空间；上游 `userId` 参数不交给模型。

## 运行诊断与数据清理

内置只读工具 `runtime_diagnostics` 提供组件状态、最近 24 小时的安全故障记录及发送任务统计，每次最多 20 条。主人私聊可查询全局状态；群聊只查询当前账号、当前群关联的故障。诊断不修改配置、不重启服务、不重发文件。

诊断历史独立保存在 `data/diagnostics/events.jsonl`（最多 1000 条、512 KiB），只保存组件、时间、故障类别及白名单错误码；模型看不到密钥、QQ 身份、文件路径、工具参数或聊天正文。

显式清除聊天与记忆前，先运行只读预检：

```bash
node --env-file-if-exists=.env --import tsx scripts/reset-memory.mjs --dry-run
```

服务停止后换成 `--execute` 执行。清理包括聊天、摘要、记忆、链接、日报、发送任务、聊天衍生 KV、文档产物及旧记忆备份；数据库使用 secure_delete、VACUUM 和 WAL 截断。人设、模型选择、模型目录、登录、主动消息计划和独立安全诊断保留。清理时间作为新记忆起点，旧消息和历史补取不会重新灌入。

## 已知边界

- 不同 OneBot 协议端的字段差异、`upload_private_file` / `get_group_msg_history` 的具体行为以实际版本实测为准；相应能力在首次真实成功前标记 `unverified`。
- 记忆提取的归因准确率未做测试集评估；candidate/confirmed 分级是保守设计，不承诺提取即正确。
- MCP 客户端为最小实现（initialize / tools.list / tools.call），不支持资源、采样等能力。
- 网页读取仅处理允许访问的公开内容；需要登录、付费或访问挑战时停止，摘要不能冒充正文。
- 群白名单/收件人的面板化修改未做（改配置文件重启）；单账号。
